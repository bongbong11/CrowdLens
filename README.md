# CrowdLens

SillyTavern용 독립 커뮤니티 반응 확장. **0.2.0부터 판독·생성·저장은 전용 서버 플러그인에서 실행합니다.** 브라우저는 시트와 최근 장면을 전달하고 설정·진행 상태·피드를 표시합니다. Jeved·Scene Reader Hub 설치에 의존하지 않습니다.

## 설치

SillyTavern 1.18.0 이상 → 확장 설치 → `https://github.com/bongbong11/CrowdLens` 입력 → 새로고침.

로컬 설치는 이 폴더 전체를 `public/scripts/extensions/third-party/CrowdLens`에 복사합니다. 빌드나 추가 패키지는 필요 없습니다.

**서버 플러그인도 설치해야 합니다.** [서버 플러그인 ZIP 다운로드](https://github.com/bongbong11/CrowdLens/raw/refs/heads/main/downloads/crowdlens-server.zip)를 풀어 `crowdlens` 폴더를 SillyTavern의 `plugins/` 안에 넣습니다. 또는 저장소의 `server-plugin/` 폴더를 `plugins/crowdlens/`로 복사합니다. 최종 경로가 `plugins/crowdlens/package.json`인지 확인하세요.

`config.yaml`에서 아래 설정을 켜고 **SillyTavern 서버를 재시작**합니다. `enableCorsProxy`는 필요 없습니다.

```yaml
enableServerPlugins: true
```

서버는 SillyTavern 루트 폴더에서 실행합니다. 플러그인만 설치하거나 브라우저만 새로고침해서는 변경이 적용되지 않습니다. 화면 확장과 서버 플러그인을 함께 업데이트하세요.

## 사용

1. 마법봉 메뉴 → **CrowdLens 설정**을 엽니다.
2. **서버 저장소 연결됨** 표시를 확인합니다. JEV 제공자는 공홈 TypeSafe와 NanoGPT 두 개만 지원합니다.
3. 해당 키를 입력하고 **JEV 키 서버에 저장**을 누릅니다. 제공자별 키는 계정별 전용 서버 파일에 저장되며 새로고침 후에도 유지됩니다. 브라우저에는 저장 여부만 반환합니다. NanoGPT는 씬판독기와 같은 구독 전용 경로를 사용하며 키의 Billing이 `Subscription only`인지 매 요청마다 확인합니다.
4. **SillyTavern에 이미 저장한 연결 프로필**을 선택하고 **사용**을 켭니다. 선택하지 않으면 서버에 저장된 현재 선택 프로필, 그것도 없으면 저장된 현재 연결 설정을 사용합니다. 서버가 프로필의 모델·서버 URL·secret ID를 읽고 기존 SillyTavern 서버 생성 경로를 호출합니다. 별도 모델 키 입력은 필요 없으며 RP 채팅의 연결 설정을 바꾸지 않습니다. Chat Completion과 Text Completion 프로필을 지원합니다. 모델 최대 출력은 기본 **8,192**, 설정 범위는 **8,000~32,768** 토큰입니다. 연결 모델 자체의 지원 범위도 충족해야 합니다.
5. **커뮤니티 선택**에서 **자동 선택** 또는 **직접 체크**를 고릅니다. 직접 체크하면 선택한 곳만 생성 후보로 쓰며, JEV는 플랫폼 선택을 건너뛰고 공개 정보·반응 가능한 집단을 확인합니다. 공개 경로나 집단이 없으면 해당 장면을 생성하지 않습니다.
6. **가장 최근 RP 응답 아래** 접이식 화면에서 **이 장면 반응 만들기**를 누릅니다. 새 응답·이벤트·채팅 변경으로 유료 생성이 자동 실행되지 않습니다. 예전 자동 생성 설정도 비활성화됩니다. 새 RP 응답이 나오면 이전 메시지의 피드는 화면에서 제거하고 최신 응답 아래에 생성 대기 화면만 표시합니다. 서버에 저장한 결과는 남아 있습니다.
7. 설정의 **커뮤니티 프롬프트 편집**을 펼치면 커뮤니티별 본문과 공통 지침을 읽고 수정할 수 있습니다. **이 커뮤니티 저장**을 눌러 적용하며 다음 생성부터 사용합니다. 커뮤니티를 전환할 때 저장하지 않은 초안은 창이 열려 있는 동안 보관하며, 창을 닫으면 저장하지 않은 초안은 사라집니다. **편집 되돌리기**는 마지막 저장 상태로 되돌립니다. 원본 JSON 파일은 수정하지 않습니다.

0.3.0 설정 화면은 구역별 카드와 접이식 상세 항목으로 구성합니다. 설정 내용에는 독립 세로 스크롤이 있고, 모바일에서는 입력을 한 열로 배치하고 플랫폼 탭은 가로로 넘깁니다. 버튼은 한글이 세로로 쌓이지 않는 가로형입니다.

UI 진입점은 마법봉 설정과 RP 메시지 아래 피드 두 곳입니다. 설정 창에는 프로필 확인·다시 판독, 브랜치, 제공자, 토큰 한도, 프롬프트 가져오기, 피드 삭제가 모여 있습니다.

모델 지시문과 JEV 판정 질문은 영어로 작성합니다. 한국어권 반응은 한국 커뮤니티 원문처럼, 해외 반응은 플랫폼의 번역 보기를 누른 듯한 매끄러운 한국어 번역으로 출력하도록 지시합니다. 외국의 표현·농담·밈·문장 리듬·이모티콘을 모두 한국 커뮤니티식으로 바꾸지 않습니다. 닉네임·고유명사·해시태그·밈·이모트는 원형을 유지할 수 있습니다. 시트와 가져온 플랫폼 프롬프트의 원문을 번역하거나 고치지는 않습니다.

각 커뮤니티를 특정 국가로 고정하지 않고 같은 피드 안에서 댓글별 문화권과 개인 성격을 섞습니다. 커뮤니티 표현 권역은 미국·유럽·동아시아로 제한하며, 닉네임으로 실제 국적·인종을 추정하지 않습니다. 지역 구분은 표현의 맥락이며 지역 간 싸움을 강제하지 않습니다. 해외 댓글은 모델 응답 안에서 해당 언어의 `originalBody`를 먼저 작성하고 이를 한국어 `body`로 옮기도록 지시합니다. 원문 초안은 표시하거나 결과 파일에 저장하지 않습니다. 화면의 국기 표시는 제거하고 원문/번역됨만 작게 표시합니다. 실제 번역 말투의 품질은 연결 모델의 지시 이행에 달려 있습니다. 장면에 어울리면 같은 댓글창에서 사소한 말꼬리·오독·딴소리로 시작하는 답글 싸움과 끼어들기를 섞습니다. 플랫폼과 개별 말투에 맞는 욕설·빈정거림·거친 표현을 순화하지 않고 번역하도록 지시하되, 모든 댓글이 싸우거나 욕하도록 강제하지 않습니다. 답글은 같은 피드의 이전 댓글만 참조할 수 있습니다.

성격은 **기질 10 × 감정 8 × 말하는 방식 6 × 거친 표현 강도 5 × 버릇 6 = 14,400가지** 조합입니다. 서버가 여러 주사위를 굴린 뒤 짧은 영어 성격 문장으로 조립해 댓글별로 전달합니다. 문화권과 반응 집단은 이 성격 축과 별도로 정합니다. 친절한 이용자부터 악의적인 트롤·천박한 드립·음흉한 뒷말·노골적인 관심종자까지 포함하며, 익명/거친 공간에는 그 출현 비중을 높입니다. 말투를 순한 단어로 바꾸는 사후 치환 필터는 없습니다. 모든 조합을 매번 고정 비율로 배치하지 않습니다.

플랫폼 편집의 **음지 커뮤니티**를 켜면 관리자 삭제 표시 없이 댓글이 남는 가상의 공간으로 취급합니다. 익명 스타일인 4chan은 기본으로 켭니다. 일반 커뮤니티에서는 모델이 드물게 `removed:true`를 반환할 수 있으며 그때만 삭제된 댓글 표시를 합니다. 거친 단어를 감지해 자동으로 삭제 표시로 바꾸는 방식은 아닙니다.

## 프로필과 장면

- 첫 반응 생성 때 연결 모델이 캐릭터 시트의 설명·성격과 현재 유저 페르소나를 읽어 짧은 프로필을 만듭니다. 시트 읽기 순서는 씬판독기의 `importCurrentSheet`와 같습니다. 캐릭터는 `character.data || character`, 페르소나는 문맥의 페르소나 설명 → 현재 아바타의 저장 항목 → 전역 페르소나 설명 순서입니다. 시나리오·노트·예시 대화·로어북은 자동으로 섞지 않습니다. 직업·인지도·대외평판·지인 관점·공개정보를 캐릭터와 유저 각각 저장합니다.
- 저장 위치는 계정별 `data/<account>/crowdlens/`입니다. 공통 설정·JEV 키·캐릭터/브랜치별 프로필·채팅/브랜치별 피드·서버 작업 기록을 별도 파일에 저장합니다. 캐릭터·채팅·브랜치 파일명은 해시로 만듭니다. 시트나 페르소나가 달라지면 다시 판독합니다. 시트·채팅 파일·캐릭터 카드 확장 필드는 수정하지 않습니다.
- 기본 브랜치는 `main`이며 화면에는 **기본 브랜치**로 표시합니다. **＋ 추가**를 누른 뒤에만 이름을 입력해 새 브랜치를 만듭니다. 목록에서 전환하면 별도 프로필과 피드로 분리되고 기존 브랜치로 돌아갈 수 있습니다. 채팅 분기는 SillyTavern의 채팅 ID로 구별합니다.
- JEV에는 짧은 프로필, 최신 RP 응답, 앞선 최대 5개 메시지를 보냅니다. 최신 장면만 판정하고 과거 메시지는 맥락으로 사용합니다. 비공개 장면에 공인이라는 이유만으로 대중 반응을 붙이지 않습니다.
- 적합한 플랫폼과 가능한 집단을 판정한 후 상황 점수에 가중치를 둔 랜덤으로 플랫폼별 8개 반응의 집단 구성·비율을 정합니다. 일반인은 지인·동료 중심으로 판단하고 실제 근거 없는 팬덤·언론 관심은 만들지 않도록 지시합니다.
- 결과는 채팅·브랜치별 최근 최대 80개 장면을 전용 서버 파일에 저장합니다. 스와이프·응답 수정·페르소나·시트·플랫폼 구성별로 구별합니다. 과거 피드는 모델에게 다시 보내지 않습니다. 장기 여론·계정 기억은 없습니다.
- 작업은 서버가 제출 당시의 장면 사본으로 실행합니다. 브라우저의 상태 조회가 없어도 계속됩니다. 탭을 닫거나 다른 화면/채팅으로 이동해도 완료 후 저장하고, 돌아오면 진행 상태·결과를 불러옵니다. 수정된 메시지에는 이전 장면의 결과를 붙이지 않습니다. 명시적인 서버 작업 취소 버튼이 있으며 실행 제한은 5분입니다.
- SillyTavern 서버 자체를 종료하면 작업도 중단됩니다. 재시작 후 중단 상태를 표시하고 수동 재생성을 안내합니다. 서버 재시작으로 유료 모델 요청을 자동 중복 실행하지 않습니다. 동시에 제출 가능한 작업은 계정당 최대 4개이며 같은 캐릭터·브랜치 프로필 작업은 순서대로 실행합니다.

## 전용 저장소와 이전

```text
data/<account>/crowdlens/
  settings.json                         공통 설정과 변경 버전
  secrets.json                          TypeSafe·NanoGPT 키 (브라우저에 반환하지 않음)
  characters/<hash>/branches/<hash>.json 사회적 프로필
  chats/<hash>/branches/<hash>.json      장면별 피드와 최근 작업
  jobs/<uuid>.json                      작업 진행·완료·실패 기록
  migration/legacy-settings-backup.json 이전 버전 원본 백업
```

기존 `extension_settings.crowdlens` 자료가 있고 새 서버 저장소가 비어 있으면 먼저 원본을 백업한 뒤 프로필·피드·설정을 이전합니다. 서버에서 같은 원본의 이전 완료를 확인한 경우에만 브라우저가 예전 CrowdLens 설정 항목을 정리합니다. 다른 원본이나 불완전한 이전은 예전 항목을 보존합니다. 기존 서버 자료를 예전 브라우저 자료로 덮어쓰지 않습니다.

서버 파일은 임시 파일에 기록·동기화한 뒤 교체하고, 여러 요청의 파일 변경은 순서대로 처리합니다. 다른 탭의 오래된 설정은 변경 버전 검사로 거부합니다. API 키는 계정 데이터 폴더의 서버 파일에 저장되며 암호화된 금고는 아닙니다. 원본 프롬프트·시트·피드는 공개 GitHub에 업로드하지 않습니다.

## 포함된 프롬프트

로컬 설치 번들에는 사용자 제공 `커뮤반응모음.json`에서 SMS 항목을 제외한 파일을 `prompts/community-reactions.json`에 포함했습니다. 남은 플랫폼의 프롬프트 본문과 사용자 원본 파일은 수정하지 않았습니다. 공개 GitHub 저장소에는 원문 공개 승인 전까지 이 파일을 포함하지 않습니다. GitHub로 설치하면 원문과 같은 9개 플랫폼의 별도 기본 안내 프롬프트가 제공되며 커뮤니티 선택 구역의 **로어북 가져오기**로 원본을 넣을 수 있습니다. 현재 목록 수와 원문 파일 적용 여부를 화면에 표시합니다. 여러 JSON 파일은 기존 목록에 합치며 같은 플랫폼 ID는 마지막 파일 내용으로 갱신합니다. SMS는 가져오기에서도 제외하며, 기존 설정에 있던 SMS도 업데이트 후 제거합니다.

Twitch, Reddit, Twitter/X, Discord, YouTube, AO3, Instagram, TikTok, 4chan의 9개 프롬프트와 공통 User Archetypes를 읽습니다. 각 플랫폼에 맞는 가벼운 CSS 스타일과 번역/권역 표식으로 렌더링합니다. 사진·영상·외부 링크를 실제로 생성하거나 소셜 서비스에 게시하지 않습니다. 좋아요·답글 작성 표시는 장식이며, 생성된 댓글 간 답글 관계는 화면에 표시합니다.

원본의 백틱/헤더 규칙은 UI의 JSON 구조와 탭으로 대체하며, 장기 사용자 기억 규칙과 예시 전용 인물·과거 사건은 현재 RP의 사실로 만들지 않도록 생성 지시를 적용합니다. 커뮤니티 말투·성격 다양성은 활용합니다. 가져온 텍스트와 생성 결과는 코드로 실행하지 않으며 결과는 `textContent`로 표시합니다.

설정에서 다른 JSON을 가져올 수 있습니다. SillyTavern 로어북 `entries`, 플랫폼 배열, `{ "platforms": [...] }`, 이름→프롬프트 문자열 객체를 지원합니다. 정규 배열 예시:

```json
{"platforms":[{"id":"forum","name":"커뮤니티","style":"board","prompt":"플랫폼별 말투와 형식 지침"}]}
```

공통 항목은 별도 플랫폼으로 노출하지 않습니다. 제공자 키는 프롬프트에 포함하지 않습니다.

## 검증

`npm test`와 `npm run check`를 실행합니다. 추가 패키지는 필요 없습니다.

로컬 프롬프트 포함 상태에서 37개 자동 테스트가 통과했습니다. 제공자 2개·NanoGPT 구독 전용 확인·입력 판독·프로필·원본 불변·출력 토큰·SMS 제외·권역·답글·수동 선택·혼합 성격 조합·삭제 표시 검증 외에, 전용 파일 저장·키 비반환·자료 이전과 원본 확인·계정/채팅/브랜치 격리·오래된 설정 충돌·중복 제출·취소·서버 재시작·SillyTavern 연결 프로필/지시 템플릿을 확인합니다. 원본 없는 공개 코드에서는 해당 파일 검증 1개를 건너뜁니다.

브라우저와 실제 임시 HTTP 서버를 함께 사용한 모의 연동에서 **생성 중 탭 닫기 → 브라우저 없이 서버 완료·파일 저장 → 새 탭에서 피드/답글 복원**을 검증했습니다. 브라우저 모델 호출은 0회였습니다. 0.3.0에서는 브랜치 추가·재접속 후 복원, 직접 체크한 플랫폼만 생성, 프롬프트 편집·저장·복원, 최신 RP에만 표시, 이벤트로 인한 자동 모델 호출 없음, 390px/320px 모바일에서 설정 스크롤과 가로형 버튼도 확인했습니다. 유료 공급자는 모의 응답이며 실제 API 키와 실제 SillyTavern 전체 인스턴스에 대한 실연동 시험은 아직입니다.

실제 SillyTavern 인스턴스와 유료 모델/API 키를 사용한 실연동 시험은 아직 하지 않았습니다. API의 성공 응답은 코드와 모의 응답으로 검증했으며 실제 서비스 가용성이나 계정 권한을 확인한 것은 아닙니다. 판정 모델의 공개성·집단 추론은 완벽하지 않을 수 있으며 반응 생성은 버튼으로만 시작합니다. 현재 지원 범위는 1:1 캐릭터 채팅입니다.
